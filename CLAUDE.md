# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Raport Eco: an offline Windows desktop app (Electron + React 19 + TypeScript + Vite) for dictating and producing echocardiography reports in Romanian. Audio is transcribed locally with whisper.cpp; nothing leaves the machine. UI strings, dictation aliases, and much domain vocabulary are Romanian.

## Commands

```
npm run dev                # compile electron/ then start Vite + native window (scripts/dev.mjs)
npm run dev:vite           # renderer only in a browser (no Electron bridge)
npm run build              # tsc -b, compile electron/, vite build
npm run lint               # eslint .
npm run test:parser        # compile pure TS modules to dist-parser-tests/ and run all tests/*.test.mjs
npm run test:pipeline      # real conversion+whisper end-to-end; needs `npm run build` first and ECHOREPORT_TEST_AUDIO set to a non-patient fixture
npm run package:portable   # release/Raport-Eco-Portable.exe (client handoff)
npm run package:installer  # NSIS installer in release/
```

Run a single parser test: `npx tsc -p tsconfig.parser.json && node --test --test-name-pattern "<test name substring>" tests/medicalParser.test.mjs`

Tests import the compiled JS from `dist-parser-tests/` (not the `.ts` sources), so always recompile via `tsconfig.parser.json` before running. `dist-parser-tests/` is committed to git — it changes whenever the parser sources change. Pure (React/DOM-free) modules under test — parser, `reportState.ts`, `measurementFields.ts`, `measurementLimits.ts`, `measurementUnits.ts`, `utils/bmi.ts`, `utils/derivedMeasurements.ts`, `utils/valueChecks.ts` — are listed in `tsconfig.parser.json` `include`; a new import from them must be added there too, and these modules must use `.js` extensions on relative imports (nodenext).

## Runtime dependencies (not in git)

`app/bin/whisper-cli.exe` (+ its DLLs), `app/models/ggml-large-v3-turbo.bin`, and `app/models/ggml-silero-v5.1.2.bin` (Silero VAD, from Hugging Face `ggml-org/whisper-vad`; optional — whisper runs without `--vad` if it is missing). Whisper runs with `-mc 0` + VAD; these won an A/B on `dictation/recordings` against no flags, an initial `--prompt` term list, and full large-v3 (all worse). It also gets `-t` = the logical core count (4–16) at below-normal priority: on an 8-core/16-thread laptop, 16 threads were ~25 % faster than whisper's default 4 with identical transcripts (2026-11-03). Path resolution in `electron/config.cts`: env vars `ECHOREPORT_WHISPER_CLI` / `ECHOREPORT_MODEL` / `ECHOREPORT_VAD_MODEL` / `ECHOREPORT_TEMP_DIR` > `echoReport.paths.json` (ignored; copy from `.example`) > default `app/` layout. When packaged, `app/` is shipped as an extraResource and resolved from `process.resourcesPath`, and the env vars (like `ECHOREPORT_DEV_SERVER_URL` in `main.cts`) are ignored: only an `echoReport.paths.json` in the `resources` folder can redirect paths.

## Architecture

**Electron process (`electron/*.cts`)** — compiled to CommonJS `.cjs` in `dist-electron/` via `tsconfig.electron.json` (the sandboxed preload requires CJS; imports between these files use `.cjs` extensions).
- `main.cts`: creates the BrowserWindow (contextIsolation, sandbox, no nodeIntegration) and registers fixed IPC handlers. Packaged builds get a minimal Romanian menu (edit + zoom; no Reload, DevTools or Help links), a hidden menu bar and `devTools: false`; dev keeps Electron's default menu. On `will-prevent-unload` (the renderer's `beforeunload`) it asks before the window closes or reloads.
- `preload.cts`: the only renderer bridge — exposes exactly `getPipelineStatus()`, `transcribeAudio(bytes, mimeType)`, `exportPdf(suggestedName)`. Keep it narrow; never expose fs, shell, child_process, or a generic command channel. Types for this bridge live in `src/types/electron.d.ts`, wrapped by `src/services/electronBridge.ts`.
- `transcription.cts`: accepts only a canonical 16 kHz mono PCM 16-bit WAV (validated by `isWhisperWav`), writes it to a `%TEMP%/echoreport-<pid>-*` dir, runs `whisper-cli -l ro`, deletes the dir in `finally` (with retries; a timed-out whisper is killed and awaited first); on quit `abortActiveTranscriptions` kills whisper and removes live session dirs, and at startup `removeStaleSessionDirectories` deletes session dirs whose owning process is gone (left by a crash) or that are older than the longest possible run — `legal/termeni.txt` promises the next start removes them. A transcript with only whisper's non-speech tags (`[BLANK_AUDIO]`) fails as `NO_SPEECH`. `main.cts` holds a single-instance lock (a second start focuses the window) and checks the sender page on every IPC handler. **No ffmpeg is shipped** (it was a GPL build): the renderer converts recordings with Chromium's decoders in `src/audio/whisperWav.ts` (self-contained, no imports, compiled by `tsconfig.audio.json` to the ignored `dist-audio/`); dev tools reuse that exact module in a hidden Electron window via `scripts/whisper-wav.mjs` → `scripts/whisper-wav-harness.cjs`. `electron-builder.yml` excludes any leftover `app/bin/ffmpeg.exe`, and its `afterPack` hook (`scripts/check-package.cjs`) fails packaging if any ffmpeg/ffprobe/ffplay `.exe` is in the output. Returns safe error codes (types in `shared.cts` / `src/types/audioPipeline.ts`), never raw stacks.
- `pdf.cts`: `echo-report:export-pdf` waits for `#printable-report`, shows Save As, uses `webContents.printToPDF()` A4 portrait. Elements with `.no-print` are hidden in print.

**Renderer data flow (`src/`)**
1. `DictationPanel` records via MediaRecorder with Chromium's voice processing on (`MICROPHONE_CONSTRAINTS`: auto gain, noise suppression, echo cancellation). Doctors use the laptop's built-in microphone, which needs the gain control; turning it off on 2026-11-05 made in-app transcripts worse, so it is always on (no toggle) → `transcriptionService` → IPC → transcript text (editable). Failsafe for a recording left on by mistake: after 30 minutes recorded, or 30 minutes in pause, it stops (microphone off) and `AutoStopDialog` asks whether to analyze it like a normal dictation or delete it (Esc does not dismiss it). Whisper's process timeout (`PROCESS_TIMEOUT_MS`, 60 min) is sized for such a 30-minute recording. After a failure that a second attempt can fix (whisper crashed or timed out, temp files failed: `RETRYABLE_ERROR_CODES` in `transcriptionService.ts`), "Reîncearcă transcrierea" transcribes the recording still in memory again; it is hidden once the doctor types into the transcript.
2. `parseEchoTranscript()` in `src/services/medicalParser.ts` turns the Romanian transcript into `ParsedEchoData` (numeric/qualitative measurements with confidence, conclusions, patient info).
3. Dictated values go straight into the form, like the patient data. `DictationPanel` sends only what changed since the previous parse (`changedDictation` for measurements and conclusions, `changedPatientFields` for the patient), so a correction typed in the form survives later edits to unrelated parts of the transcript. `App.tsx` keeps a `ReportForm` (`services/reportState.ts`, pure, unit-tested): the `EchoReport`, a `DictationNote` per uncertain dictated field, and the last value dictation put in each field. `applyDictation` puts the first dictated value in the field, recalculates the ratios (`utils/derivedMeasurements.ts`: E/A, E'/A', E/E'; dictated ratios are ignored) and adds a note shown under the field (`DictationNoteView`). Notes with warnings (several different values, ambiguous number, low confidence, unit mismatch, replaced a value the doctor typed) block the preview until the doctor clicks "Confirmă", picks another dictated value or "Revino la …" (`resolveNote`), or edits the field (`editField`); info notes (unit converted, approximate) never block. The callbacks passed to `DictationPanel` must stay referentially stable — the panel re-sends on every effect run with changed deps. "Șterge formularul" remounts `DictationPanel` via `key` to drop the previous patient's transcript.
   Unsaved work: `App` keeps the report as started or last exported to PDF; while the report differs from it (`isSameReport`) or the panel holds audio not yet in the form (`onAudioPendingChange`: recording, paused, transcribing, auto-stopped), "Șterge formularul" asks via `ConfirmDialog` and `beforeunload` is cancelled, so closing or reloading asks in main. A successful export resets that baseline, so the normal flow (export, then clear or close) asks nothing.
4. Form components edit the report; `ReportPreviewPage`/`ReportPreview` render the printable report used for PDF export.

`src/types/echoReport.ts` defines `EchoReport` / `Measurements` (all values are strings; keys are the `MeasurementKey` union used everywhere). `src/config/measurementFields.ts` is the single registry of every measurement's form section, label, unit, report label, and review label; the forms (`MeasurementGroup`), report rows, review labels, derived-key list, and `MEASUREMENT_UNITS` are all generated from it (a test asserts it covers every key once). Adding a measurement means touching the type, the registry, its limits, the parser's alias definitions, and placing a `<Field k=…>` in the report layout (`ReportPreview.tsx`, which keeps its hand-built print layout).

**Value checks.** `src/config/measurementLimits.ts` transcribes `echo_measurement_limits.xlsx` (repo root; the limits still need a cardiologist's review): per numeric field (and patient age/weight/height) Reject and Confirm bounds in the stored unit, plus max decimals; a test asserts every numeric registry field has limits. `src/utils/valueChecks.ts` (pure) applies them:
- Typing only filters characters (`sanitizeNumericInput`: digits, one separator, comma → dot, capped decimals).
- `MeasurementField` shows the status only when the field is not focused: red for impossible values, amber with a "Confirmă" button for unusual ones.
- `crossFieldWarnings` (end-systolic > end-diastolic, Pmean > Pmax, Pmax vs 4·Vmax²) only warns.
- `findReportIssues` blocks "Previzualizare raport" while any value is impossible, unusual and unconfirmed, or dictated with an unresolved warning, listing them in `ReportActions`.
- Confirmations live in `App` as field id → value, so editing a value drops its confirmation.
- Dictated out-of-range values are kept in the form and flagged like typed ones; a field shows a single "Confirmă", which confirms an unusual value and settles its dictation note together.
- Derived fields (ratios, BMI) are read-only. Textareas are capped at 500 characters, conclusions at 5,000.

The register number ("Nr. curent") is consumed only by a successful PDF export, which stores exported+1 in localStorage (`ecocard-next-current-number`); the next number appears when a new report is started. The clinic header (name, address) printed on the report is edited via "⚙ Setări" (`SettingsDialog`) and stored in localStorage (`ecocard-clinic-settings`, parsed by the pure `src/config/clinicSettings.ts`). It starts empty — the app ships to several doctors, so never hard-code a clinic's name or address. `src/dev/testReport.ts` is a dev-only fixture behind an `import.meta.env.DEV` button.

`legal/termeni.txt` (intended purpose, warnings, licence, privacy notice; UTF-8 with BOM) is the single source for the NSIS license page and the in-app `AboutDialog` ("Despre", imported via `?raw` in `src/config/appInfo.ts`). On first start, and whenever its `Versiunea termenilor` line changes, the app blocks until the doctor accepts (`ecocard-terms-accepted` in localStorage). The privacy section describes exactly what is stored where; update it when data handling changes. `legal/THIRD_PARTY_NOTICES.txt` holds the full licence text of every bundled component (whisper.cpp/ggml, the Whisper and Silero models, React, Electron) with versions; it ships next to the exe (`extraFiles`) and in "Despre". `scripts/check-package.cjs` fails packaging if a file in `resources/app` is not named in it, and `tests/thirdPartyNotices.test.mjs` fails when the installed React/Electron versions drift from it. `SDL2.dll` and `parakeet.dll` from the whisper.cpp release are excluded (whisper-cli does not need them). The app version comes from `package.json` via Vite's `__APP_VERSION__` define.

## Medical parser (`src/services/medicalParser.ts` + `src/services/parserAliases.ts`)

The core and most-edited logic. `parserAliases.ts` is pure data (everything whisper-specific: `CONTEXT_ALIASES`, `NUMERIC_FIELDS`, `QUALITATIVE_FIELDS`, `KNOWN_QUALITATIVE_VALUES`, `ABBREVIATION_REPLACEMENTS`, `TYPO_REPLACEMENTS`); `medicalParser.ts` is the matching logic. Whisper fixes normally touch only `parserAliases.ts`. Key mechanics:
- Text is normalized (lowercase `ro-RO`, diacritics stripped, ș/ț → s/t, whitespace/hyphens collapsed, decimal commas → dots, abbreviation fixes like `V.S.` → `vs`, and known Whisper mis-transcription fixes) while `normalizeWithIndex` keeps a `rawIndex` map back to the original transcript. Rewrite rules live once in `ABBREVIATION_REPLACEMENTS` / `TYPO_REPLACEMENTS`; `normalize()` is just `normalizeWithIndex().text`. A typo rule may change the length: `mapRewriteIndices` keeps `rawIndex` aligned for any rule. **Aliases must therefore be written in normalized form** (lowercase, no diacritics).
- `NUMERIC_FIELDS` / `QUALITATIVE_FIELDS` are alias tables per `MeasurementKey`. Whisper variants (split words, typos like "telediastoric") are handled by adding aliases or a normalization step.
- Matching: at each position the longest alias wins; aliases starting inside an already-consumed span are skipped. Section headings (`CONTEXT_ALIASES`, e.g. aortic/LVOT/mitral flow) set an active `FlowContext` that disambiguates shared aliases like "vmax"; `context` / `excludeContexts` on a field def control this.
- The value window runs from the alias end to the next match; numbers come from `romanianNumberParser.ts` (spoken Romanian numerals, "virgulă" decimals) and units from `unitNormalizer.ts`. A spoken unit that differs from the field's unit in `MEASUREMENT_UNITS` is converted (mm↔cm, mm/s and m/s→cm/s, `convertedFrom`) or flagged `unitMismatch` (a warning under the field). Commas don't end a window, so a misheard label lets its number leak into the previous field; a window with several numbers proposes the first one as `ambiguousValue` (low confidence, a warning under the field) rather than dropping the field.
- Whisper often writes "telesistolic" as "telediastolic": when the end-diastolic diameter or volume label comes exactly twice, back to back, the end-systolic field got nothing and the second value is smaller, `reassignRepeatedDiastolic` moves it to the end-systolic field with `heardAs` (a warning under the field).
- Text after "concluzii" is extracted as conclusions and excluded from measurement parsing; patient name/age/weight/height are pulled by label regexes.

When fixing a parser bug, add a regression test in `tests/medicalParser.test.mjs` using a realistic Whisper-style transcript.

## Dictation test loop (`dictation/`)

- `dictation/scripts/<name>.txt` is a text the doctor reads aloud; `<name>.expected.json` holds its expected patient data, every dictated measurement (all numeric values unique, so misplaced values are identifiable) and conclusions. Derived ratios are computed, not listed. `"scope": "numeric"` marks a labels-and-numbers-only script (e.g. `numeric`) that covers just the measurements with a unit.
- Recordings go in `dictation/recordings/<script>-<anything>.m4a|wav|webm|ogg|mp3` (git-ignored, stays local). Phone recordings test the parser but not the app's microphone path: to measure what doctors get, record in `npm run dev` with the laptop microphone and save it with the panel's "Descarcă înregistrarea (dev)" (`dictare-app-<date>.webm`; replace `dictare` with the script name). `npm run eval:dictation [-- <filter>] [--retranscribe] [--all] [--json]` transcribes new recordings with the app's own Chromium WAV conversion + whisper into `dictation/transcripts/<name>.txt` (committed, cached), then reports per field `OK` / `OK*` (right value or offered as a choice, but with a warning under the field) / `WRONG` / `MISPLACED` / `MISSING` with transcript excerpts. Logic lives in `scripts/dictation-check.mjs`. Each recording also gets a word error rate (WER) against the script text, which measures the speech recognition apart from the parser. NVIDIA Parakeet TDT 0.6B v3 (sherpa-onnx) was benchmarked against whisper on these recordings on 2026-11-08 and rejected: WER 57–75 % vs 31–49 %, and it got the numbers themselves wrong.
- `tests/dictation.test.mjs` (part of `test:parser`) requires each script's text to parse perfectly and every committed transcript to keep passing, except entries in `dictation/known-issues.json` (unrecoverable whisper output, with a reason).
- `/fix-dictation` (`.claude/skills/fix-dictation/SKILL.md`) is the procedure for turning a new recording's failures into parser fixes. Never edit transcripts or expected values to make a check pass.

`/push-master` (`.claude/skills/push-master/SKILL.md`) verifies (tests, lint, typecheck), commits everything and pushes to `origin/master`; it refuses to commit audio, PDFs, runtime binaries or local config.
